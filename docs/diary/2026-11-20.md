## 1. Store launch

- **What:** iOS 1.0.0 (5) and Android 1.0.0 (4) went live. Releases are manual on both stores: App Store "Release", Play "Publish" (managed publishing).
- **Why manual:** the owners decide the launch moment (pilot accounts first).
- **How:** Play first refused to turn managed publishing on ("You can't turn on managed publishing right now"); it accepted once the production release had been saved, and only then were the 12 changes sent for review.
  App Store: the first subscriptions of an app cannot be submitted by API (`FIRST_SUBSCRIPTION_MUST_BE_SUBMITTED_ON_VERSION`); version 1.0.0, the subscription group and all 36 subscriptions were added to one draft submission in the App Store Connect website and submitted together.
- **Links:** App Store https://apps.apple.com/tr/app/id6834434284 · Google Play https://play.google.com/store/apps/details?id=io.anahtar.app
- **Note:** right after release the App Store page answered 404 for some hours (Apple CDN propagation); the version state was already `READY_FOR_DISTRIBUTION`.

## 5. Apple App Store Server Notifications → RevenueCat

- **What:** App Store Connect production and sandbox notification URLs (version 2) now point to RevenueCat's endpoint for the App Store app; read-back matches RevenueCat exactly. Google RTDN was already connected.
- **Why:** without it cancellations, refunds and billing issues from Apple reach RevenueCat (and our webhook) late.
- **How:** RevenueCat only reveals the URL after the account password is re-entered (done by a human); the value was copied through the clipboard and set via the App Store Connect API, never printed. RevenueCat shows "No notifications received" until the first Apple event.

## 6. Store rename (#136)

- **What:** "Anahtar: Kiranın Anahtarı" (TR) / "Anahtar: The Key to Renting" (EN), asked by the owners. Store names only; the app's home-screen label and the website keep "anahtar".
- **Play:** listing titles changed via API (first attempt got a transient 503; retried). With managed publishing ON the change needs **Publish** after Google's review.
- **App Store:** the name is locked while a version is live; it changes only with a new version. Version **1.0.1** was created with the new names and release notes; build 1.0.1 (6) auto-submits, then the version goes to App Review with manual release.
- **runtimeVersion pin:** `app.json` used `runtimeVersion.policy = appVersion`; bumping to 1.0.1 would have split OTAs into two runtimes (1.0.0 installs would stop getting updates). The native code is identical to 1.0.0 (5), so `runtimeVersion` is now the fixed string `"1.0.0"`. **Raise it only together with a native change and a new store build.**

## Lessons

1. **First subscriptions go with a version, in the website.** The API refuses them (`FIRST_SUBSCRIPTION_MUST_BE_SUBMITTED_ON_VERSION`); later subscriptions can be submitted alone.
2. **Managed publishing on a new Play app** could only be turned on after the production release was saved.
3. **App Store names are locked while live**; renaming needs a new version and review. Play titles can change any time (still reviewed).
4. **`runtimeVersion` policy `appVersion` + a version bump** silently cuts older installs off OTAs. Pin the runtime when native code is unchanged.
5. **`supabase functions deploy` from a folder Docker cannot see** fails with "entrypoint path does not exist"; `--use-api` bundles on Supabase's side.
6. **Play API 503s are transient**; retry the whole edit.
7. **Play service-account 403 on monetization** was a missing permission ("View financial data" + "Manage orders and subscriptions"), not propagation delay.
8. **A follow-up migration also needs its old tests updated** — grep tests for the behaviour being closed (here: direct `system` inserts), not only the files the spec lists.
9. **Copying a password file with `pbcopy` includes the trailing newline**; pasted into a phone field it fails login. Password files are written without a newline.
10. **A second email channel is easy to add by accident**: in-app notifications are already mailed by the push function (respecting opt-out). Do not also queue `mail_outbox` for the same event.
11. **Check who the CLI is logged in as** (`eas whoami`): a different Expo account has no access to the project.
