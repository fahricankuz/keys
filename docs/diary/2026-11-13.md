## 1. Audits

- **What:** seven read-only audits ran in parallel: database authorization and storage, Edge Functions and client auth, live Supabase configuration, mobile store readiness, in-app purchase and RevenueCat, Sentry plan, web/DNS/CI. Plus live read-only SQL against production (`nfpefnrgtnwvclwbriaw`).
- **Why:** Erdem wanted to ship to both stores; nobody had looked at the security of the live system as a whole.
- **Confirmed live holes:** a tenant could make themselves a landlord (`memberships.role` update); `site_report` callable without a session; a property id could collide with a storage folder (`site-`, `hukuk-` prefixes) and expose another party's legal files;
  invite codes were guessable and the anonymous preview leaked resident personal data; a blocked person could bypass the block through `system` messages; moving a document skipped its review; no file size/type limits;
  webhook and cron definitions carried plaintext secrets, one of which equalled the `info@anahtar.io` mailbox password.
- **Evidence:** the spec's header and requirements (R1 to R5 and following); every finding got a test in the fix PR.
- **Decision:** fix before any store build, as one combined PR plus a sequenced runbook.

## Lessons

1. **Implicit-flow tokens in URLs are a leak.** The client used the implicit auth flow, which puts session tokens in the URL fragment (history, referrers, logs, Sentry breadcrumbs). Switched to **PKCE** with one-time codes
   (`setSession` is gone); links must be opened on the device that requested them, and phone sessions live in SecureStore/Keychain.
2. **Fake-backend tests miss real-environment paths.** The suite builds against a fake Supabase, so a static SSR build with real settings was never exercised (PR #113). Rule: when you touch session, storage or build code, also run `expo export -p web` with real `EXPO_PUBLIC_*` values.
3. **Hardening has knock-on effects.** Requiring invite codes broke the demo-account script (#114); closing a write path would break the old client (hence the follow-up migrations and the 24-hour rule). Grep for callers, including scripts, before tightening.
4. **The site deploys before migrations.** Every migration must work with the client currently live and with open stale tabs; add first, remove later in a separate PR.
5. **Never translate at module load.** Language is decided after imports; read translations when used (PR #116).
6. **Apple Distribution certificate limit:** a team can only hold a few; if EAS cannot create one, create it manually and upload it (keep key, certificate and `.p12` in the local secrets folder; the certificate expires 2027-11-13).
7. **Org policy exceptions: scope them to the project.** Resetting `iam.allowedPolicyMemberDomains` on `anahtario` only kept the exception small.
8. **Play API/service-account permissions propagate slowly;** plan a wait before scripted subscription creation.
9. **Re-authorise tools after moving to a new org** (Sentry MCP pointed at the old US org).
10. **OTA and environment variables:** `eas update` does not use `eas.json` build `env`; verify the bundle has a backend before the first production OTA.
11. **A WebView needs an explicit origin allow-list and a page it may load;** a third-party widget flow on a critical path (login) needs a device test before release. Turnstile is not enforced by Supabase, so removing it on phones lost no enforced protection.
12. **Console work needs Erdem's login;** agents continue after he signs in and never type passwords. The secrets folder is the hand-off point, never chat.
13. **Branch renames touch CI triggers:** change triggers first, rename second (section 11).
14. **Staging is not production:** no pg_cron, pg_net or Vault there, so staging plans cannot prove those parts; verify them in production with the read-only checks.
